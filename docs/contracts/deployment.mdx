## Deploying to a New Chain

### Prerequisites

- [Foundry](https://book.getfoundry.sh/) installed
- RPC URL for the target chain
- Deployer private key with ETH for gas
- USDC contract address on the target chain

### Steps

```bash
cd packages/contracts

# 1. Set environment variables
export RPC_URL="https://..."
export PRIVATE_KEY="0x..."
export CHAIN_ID=8453

# 2. Run the deploy script
forge script script/Deploy.s.sol \
  --rpc-url $RPC_URL \
  --private-key $PRIVATE_KEY \
  --broadcast \
  --verify

# 3. Verify contracts (if Etherscan API available)
forge verify-contract <address> OpenGrantRegistry \
  --rpc-url $RPC_URL \
  --etherscan-api-key $ETHERSCAN_KEY
```

### Deploy Script

The deploy script (`packages/contracts/script/Deploy.s.sol`) handles:

1. Deploy Registry implementation + UUPS proxy
2. Deploy Payments contract (linked to Registry)
3. Deploy Factory (linked to Registry)
4. Deploy GRANTToken
5. Deploy GRANTStaking (linked to GRANTToken)
6. Deploy FeeDiscountOracle (linked to GRANTStaking)
7. Deploy Escrow (with authorized signer)
8. Configure bidirectional links

### Verification with Blockscout

For chains without Etherscan API support (or where it requires a paid plan), use Blockscout:

```toml
# foundry.toml
[etherscan]
base-sepolia = { key = "verifyContract", url = "https://base-sepolia.blockscout.com/api/" }
```

```bash
forge verify-contract <address> ContractName \
  --chain-id 84532 \
  --verifier-url "https://base-sepolia.blockscout.com/api/" \
  --etherscan-api-key "verifyContract"
```

## Adding a New Chain to the SDK

After deploying contracts to a new chain:

1. Add the chain config to `packages/sdk/src/constants.ts`:

```typescript
// In SUPPORTED_CHAINS
12345: {
  chainId: 12345,
  name: "New Chain",
  network: "eip155:12345",
  usdc: "0x...", // Native Circle USDC address
  rpcUrl: "https://rpc.newchain.example.com",
  testnet: false,
},
```

2. Add the chain to the API config (environment variable `CHAIN_ID`)

3. Update the deploy scripts in `packages/contracts/script/`

That's all that's needed — the SDK and API auto-resolve USDC addresses and CAIP-2 network identifiers from the chain configuration.
